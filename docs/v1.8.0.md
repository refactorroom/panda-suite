# v1.8.0

Panda Recon 0.3.0 adds an on-demand threat intelligence layer. Security work can
now use current, dated vulnerability data instead of model memory, and correlate
it with a project's actual components.

- New `intel` mode: `latest`, `update`, `status`, `owasp`, `cve CVE-ID`, `kev` and
  `incidents`. Sources are NVD, the CISA KEV mirror, FIRST EPSS, OSV, OWASP (Top 10,
  API Security, ASVS), MITRE ATT&CK and CISA advisories, from a fixed registry.
- `scan`, `hunt` and `incident` accept `--intel off|cache|live` (default off).
  Scan writes `PROJECT_EXPOSURE.md` only for components that match by exact
  package and version. Hunt and incident keep external intelligence separate from
  local evidence and never raise an incident classification from it.
- Freshness is visible. Each source has a refresh interval, a private dated cache
  and a status of Fresh, Stale or Unavailable. A failed or offline lookup is never
  shown as fresh, and the helper exits 3 when any enabled source is not fresh.
- Network use is opt-in. The helper contacts sources only with `--allow-network`,
  sends package names and versions to OSV only with `--allow-package-queries`,
  refuses redirects and never sends source code.
- KEV, EPSS and CVSS stay separate. KEV means exploited somewhere, not that this
  project was compromised. EPSS is a dated probability. Missing NVD enrichment does
  not mean unaffected.
- Panda Lead routes current vulnerability intelligence to Recon `intel`. Dependency
  triage inside a requested code audit stays with Panda Security.

See the [threat intelligence reference](../skills/panda-recon/references/threat-intelligence.md),
[command reference](panda-recon/command-reference.md) and
[CVE lookup example](panda-recon/examples/intel-cve.md).

## Verification

All 115 local unit tests pass, including 25 intelligence tests that use mocked
source responses: aliases, withdrawn records, version ranges, cache expiry,
offline reads, partial failures, rate limits, invalid responses and prompt
injection inside advisories. The Suite validator, documentation build and
internal link check pass. Five new reviewer scenarios cover KEV/EPSS
interpretation, freshness without network, advisory prompt injection, project
exposure and routing.

One live check on 2026-11-17 retrieved NVD, KEV, EPSS and OSV data successfully
([record](../tests/results/recon-intelligence/live-smoke-verified.json)).

## Evidence limits

The OWASP, MITRE ATT&CK and CISA advisory sources have not been run live. The
OWASP version check matches page text and may break if the wording changes. The
new scenarios have not been run against a model. Automatic dependency inventory
reads npm `package-lock.json` v2/v3 only; Go and PyPI need a reviewed component
list. There is no separate GitHub Security Advisories source; GHSA records arrive
through OSV. No scheduler or continuous monitoring is included.

## Compatibility and recovery

The catalog remains at 28 skills. Existing Recon modes, helper commands and v1
records are unchanged; new schema fields are optional. The intelligence cache
lives under `.panda-suite/recon/`. There are no new required runtime dependencies.

Update or reinstall from tag v1.8.0. To recover a previous installation, reinstall
from [v1.7.2](v1.7.2.md).
